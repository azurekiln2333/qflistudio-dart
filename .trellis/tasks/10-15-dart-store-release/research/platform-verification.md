## Product and terminal integrity

Both `TerminalPane` and `TerminaxTerminalPage` use the real Dart profile delegate.
Source run, numeric failure status, Stop/recovery and session transcript retention
are covered by real widget mounts. Android raw VM arguments never contain CLI
verbs such as `run` or `compile`.

The supported local command set is run/shorthand, native Kernel compilation,
formatting, syntax diagnostics, version and help. `dart analyze` is explicitly a
scanner/parser check, not project-wide semantic analysis. Network package
management is refused; unsupported commands give explicit messages.

Android/desktop use the official VM and source-free `.dill`; OHOS uses the
portable evaluator and EVC. Portable targets decline Kernel operations honestly.
There is no claim of full official-SDK parity on OHOS.

Shared gates hide Git/cloud pull, cloud terminals/projects, login/community and
AI settings; they also stop offline task synchronization and refresh shortcuts.
Android APK inspection finds no INTERNET permission. OHOS has only
READ_PASTEBOARD: INTERNET, AccountKit/login integration and AgreementReader are
removed while local file selection/sharing/preview are retained.

## Final Android artifact and packaging repair

```powershell
flutter --suppress-analytics build apk --release --target-platform android-arm64 --no-pub --target lib/main.dart
```

Artifact: `build/dartwing-release.apk` (also the standard
`build/app/outputs/flutter-apk/app-release.apk`),160,403,568 bytes (153.0MiB).

SHA256: `29b0f14d92b65b2c4fa97febbb8c4f34e3238c637900f8733b21be92406268fb`.

The original ARM64 build accidentally included x86_64 SDK libraries without
x86_64 `libflutter.so`/`libapp.so`, falsely advertising an unusable ABI. An
independent Pi confirmed the final-APK inventory. Gradle now derives validation,
build-type ABI filters and SDK asset exclusion from one requested target list.
Changing only defaultConfig filters failed because Flutter also supplies
build-type filters; final-APK inspection caught this during verification.

The final APK advertises only `arm64-v8a`; `libflutter.so`, `libapp.so` and
`libqfli_dartvm.so` are present, and unselected x86_64 ZIP/manifest/native payloads
are absent. `aapt dump permissions` contains only the app's receiver permission,
with no INTERNET permission. Size fell from 350.5MiB to 153.0MiB.

The follow-up audit checked every packaged native ELF, including `libapp.so`
and `libflutter.so`, rather than inferring their compatibility from SDK staging.
All17 are ARM64 ELF64 with every PT_LOAD alignment0x10000 (64KiB) and compatible
file/virtual offsets for16KiB pages. All are compressed/extracted libraries.
Android `zipalign -c -P 16 -v 4` also succeeds on the exact29b0f14d APK. Logs:
`build/dart-final-apk-elf-alignment.log` and `build/dart-final-apk-zipalign.log`.
This is package alignment evidence; it does not claim execution on a16KiB device.

This is a local-verification release APK using the existing debug signing key.
A store signing key is required before publication. x86_64 device execution,
Apple platforms and Linux are not established by this ARM64/Windows run.
