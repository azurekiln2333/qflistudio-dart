# Directory Structure (Backend / Dart & Platform Runtime)

> Where non-UI Dart code lives in this repository.

---

## Overview

This is **not** a client/server project. `qfli_dart` is the
`QFLIDartWing` Flutter app: an offline Dart IDE that bundles native Dart SDKs
and runs user programs on-device. "Backend" here means **runtime, toolchain,
runner, content, and platform-packaging code** — everything that is not a
widget. There is no HTTP server, no routing layer, and no database.

The shared, non-Dart UI/editor/terminal chrome lives in the sibling package
`../qfli_studio_core` (see [README.md](../../../README.md)); this repository
depends on it by path and does not vendor it.

---

## Directory Layout

```text
qfli_dart/
├── lib/                      # App runtime + widget wiring (this spec)
│   ├── main.dart             # StudioProfile + entry point (product identity)
│   ├── dart_runner.dart      # DartProgramRunner + terminal `dart` hook
│   ├── dart_tools.dart       # format / syntax diagnostics / EVC compile
│   ├── dart_project_sources.dart  # project → package map for dart_eval
│   ├── native_dart_toolchain.dart # official SDK process runner + kernel compile
│   ├── android_dart_sdk.dart # Android SDK MethodChannel bridge + layout
│   ├── dart_content_repository.dart # Dart-only offline content assets
│   ├── dart_tools_page.dart  # Dart Tools page (StatefulWidget)
│   └── names change only with a product reason
├── curriculum/               # Authored 120-lesson source (see dart-curriculum.md)
├── assets/content/           # Generated dart_{tutorials,examples}.json
├── tool/                     # Build/verify scripts run with `dart run`
│   ├── build_dart_content.dart
│   ├── verify_dart_content.dart
│   └── audit_compat.dart
├── native/                   # Bundled Dart SDK artifacts + Android JNI libs
├── android/  ios/  ohos/  linux/  macos/  windows/  web/  # Flutter platforms
└── test/                     # flutter_test suites (see quality-guidelines.md)
```

## Module Organization

- **One concern per file**, top-level class or `abstract final class` of static
  helpers. `DartTools` (`lib/dart_tools.dart`) is a pure static facade; the
  toolchain (`lib/native_dart_toolchain.dart`) is an instanceable class so tests
  can inject an `executable`.
- **Product identity is centralized** in `lib/main.dart`'s `dartProfile`
  (`StudioProfile`). Runtime capability (`runtimeKind`/`runtimeStatus`), the
  runner, templates, entry file names, and the content repository are all wired
  there. Do not scatter product policy into widgets.
- **Pure logic is separated from process/IO.** `DartProjectSources` resolves a
  project into a `packages` map with no process spawning; `DartTools.format`
  and `.syntaxDiagnostics` are pure functions; only `NativeDartToolchain` and
  `DartProgramRunner` touch processes and isolates.
- **Generated content is distinct from authored content.** `curriculum/**` is
  authored; `assets/content/dart_*.json` is generated by `tool/build_dart_content.dart`
  and committed. Never hand-edit the JSON.
- **Tools are scripts, not library code.** `tool/*.dart` is invoked with
  `dart run tool/<name>.dart` and is allowed to `print` and `exit`.

## Naming Conventions

- Files: `snake_case.dart`; one primary type per file, named to match the file
  (`native_dart_toolchain.dart` → `NativeDartToolchain`,
  `dart_content_repository.dart` → `DartContentRepository`).
- Private helpers on a class: leading underscore methods (`_readSources`,
  `_persistCurrent`). File-private top-level functions: leading underscore
  (`_scanDartFiles` in `lib/dart_tools_page.dart`).
- Static capability checks: a `static bool get supported` on the class that
  owns the platform gate (`NativeDartToolchain.supported` in
  `lib/native_dart_toolchain.dart`).
- Constants: `static const` with a descriptive name (`AndroidDartSdk._channel`,
  `ExampleCodeStore.contentVersion`). Exit-code constants come from the core
  (`kProgramNotRunExitCode`) rather than being redefined.

## Examples

- Platform-gated process execution with an injectable executable:
  `lib/native_dart_toolchain.dart` (`NativeDartToolchain.run` / `runCommand`).
- Pure compile/format/diagnostics facade: `lib/dart_tools.dart`.
- Project → package map for the portable engine: `lib/dart_project_sources.dart`.
- Platform channel SDK layout + probe: `lib/android_dart_sdk.dart`.
- Profile-based product wiring: `lib/main.dart`.

## When a new file is needed

- New **runtime capability** (new engine, new compile target): add it beside
  `dart_runner.dart` / `native_dart_toolchain.dart` and wire a gate in
  `NativeDartToolchain.supported` or the profile, not inside a widget.
- New **generated content**: extend `curriculum/**` + `tool/build_dart_content.dart`
  (see [dart-curriculum.md](../frontend/dart-curriculum.md)).
- New **UI surface**: `lib/<feature>_page.dart` as a `StatefulWidget`, following
  [state-management.md](../frontend/state-management.md).
